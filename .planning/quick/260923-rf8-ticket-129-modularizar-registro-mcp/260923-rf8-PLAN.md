# Ticket 129 — Modularizar el registro MCP

## Objetivo

Separar las 18 tools MCP por familias sin cambiar su catálogo, autorización,
paginación, idempotencia ni respuestas estructuradas.

## Trabajo

1. Caracterizar antes del movimiento el contrato completo de nombres,
   descripciones, input schemas y annotations mediante un hash estable.
2. Extraer el contexto compartido de respuesta, principal, servicios y
   autorización de recursos.
3. Separar proyectos/Epics, tickets/actividad, preguntas/comentarios y
   workflow/code links, conservando scopes y allowlists en cada handler.
4. Mantener `tools.ts` como composición compatible del servidor.
5. Comparar mecánicamente los 18 registros y ejecutar la suite MCP completa.
6. Revisar el onboarding; documentar explícitamente que la organización interna
   no cambia el contrato público.
7. Completar gates, publicar imagen inmutable y verificar producción.

## Riesgos y rollback

- Riesgo: cambiar silenciosamente un schema, annotation o fingerprint.
- Control: hash exacto del catálogo, comparación estructural y suite MCP real.
- Riesgo: esconder permisos en una abstracción genérica.
- Control: `requireScope`, proyecto, cursor e idempotencia permanecen junto a
  cada tool; sólo el lookup permitido y la respuesta son helpers compartidos.
- Rollback: revertir el commit de código; no hay migración ni cambio de contrato.
