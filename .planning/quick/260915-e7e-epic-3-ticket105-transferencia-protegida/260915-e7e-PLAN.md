## 1. Transfer protocol

Server-owned short-lived proposal, selected eligible verified member, current
Owner/workspace versions, explicit typed confirmation. Both participants must
recently authenticate; use authoritative session creation/auth proof, never
client-supplied timestamps. A stolen old session or invitation/email alone cannot
complete transfer. Describe Google's existing-account session reuse honestly,
not as forced password/MFA. Single atomic acceptance, replay/cancellation/expiry
and concurrent proposals fail safely. No multiple Owners/no ownerless intermediate
state. Preserve current one-owned-workspace-per-person constraint unless a proven
requirement needs a separately documented change; otherwise clear eligibility.

## 2. Reconciliation and recovery

Reconcile canonical workspace owner and memberships, current issue human_owner_id
with version bump, one immutable administrative event preserving prior actors.
Former Owner becomes Member with explicit edit grants for projects already
accessible as Owner; this retains existing access, not admin or future-project
access. Preserve agent identities/scopes and unrelated workspace/global sessions;
review Chrome current binding/capabilities. No shared/recovery password generation
or privileges based on knowing email. Operator recovery remains separate; verify
its behavior after transfer in disposable data, backup and document precise scope.
