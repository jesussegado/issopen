# Ticket 128 — Centralizar validación HTTP

## Objetivo

Eliminar parsers de transporte y serializadores de error equivalentes de los
routers REST sin mover reglas de negocio fuera del dominio ni alterar contratos.

## Trabajo

1. Caracterizar campos Zod, JSON malformado, identificadores y cada código de
   `DomainError`.
2. Extraer primitivas pequeñas para body, query, params y respuesta de error.
3. Migrar tracker, agentes, invitaciones, Owners, ownership, perfiles, cuenta y
   workspace conservando mensajes y status.
4. Añadir una frontera de arquitectura que impida reintroducir duplicación.
5. Ejecutar regresión completa, publicar imagen inmutable y verificar Argo,
   readiness, digest, reinicios y PVCs antes de devolver el ticket a revisión.

## Riesgos y rollback

- Riesgo: modificar un cuerpo de error consumido por web o Chrome.
- Control: contratos exactos más las suites HTTP/integración existentes.
- Rollback: restaurar la imagen y revisión GitOps anterior; no hay migración SQL
  ni transformación de datos.
